=> Added challenge route to prevent users from spoofing emails:
    Here’s how it gets used:
    1. Buyer signs in through Phantom Connect, using Google/Apple or an existing wallet.
    2. Frontend gets their wallet address automatically.
    3. If they don’t already have a valid Circuit session, the frontend requests a challenge.
    4. Backend saves a unique message in the challenge table and returns it.
    5. Frontend asks Phantom to sign that message.
    6. Backend verifies the signature, marks the challenge used, and issues a Circuit session token.

=> Anchor findings

Current behavior	                                                What needs changing
Any signer can call create_drop; there is no brand authorization	Require an initialization authorization tied to Circuit’s brand permissions
Drop addresses depend only on the edition slug	                    Prevent another wallet from claiming the same drop address first
New drops immediately become active = true	                        Separate initialization from activation
Any signer can call register_order repeatedly without payment	    Restrict supply increments to verified purchases through escrow
Escrow accepts the caller’s amount and recipient without checking a drop	Bind checkout to the intended drop, recipient and authorized price
Escrow creation and supply registration are separate	            Make payment and supply accounting atomic
Escrow address uses only drop ID and buyer	                        Introduce order identity if a buyer can purchase the same drop more than once
There’s a concrete ID-length bug: both programs permit 64-byte drop IDs while using the ID directly as a PDA seed. Solana permits 32 bytes per seed, which is why our database/API already enforce that limit.
